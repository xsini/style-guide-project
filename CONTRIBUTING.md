# Внесение изменений

## Предложение изменения

Опишите проблему, читателя, затронутую страницу и ожидаемый результат в issue или описании PR. Сначала проверьте, нет ли такого правила в руководстве. Создайте отдельную ветку от актуальной main.

```bash
git switch main
git pull --ff-only
git switch -c docs/add-accessibility
```

## Сообщения коммитов

Используйте Conventional Commits: `тип(область): краткое описание`. Область необязательна. Тип `docs` обозначает содержание документации, `fix` — исправление ошибки, `ci` — автоматизацию, `chore` — обслуживание инструментов. Используйте один язык последовательно в рамках PR.

```text
docs(accessibility): add text accessibility rules
docs(accessibility): clarify link examples after review
ci: add strict documentation build
```

Не объединяйте несвязанные изменения в один коммит. Не включайте секреты, реальные данные пользователей, node_modules и каталог site.

## Локальная сборка

Подготовьте среду по README. Затем выполните:

```powershell
npm run lint:md
.\.venv\Scripts\python.exe scripts/check_docs.py
.\.venv\Scripts\python.exe -m mkdocs build --strict
.\.venv\Scripts\python.exe -m mkdocs serve
```

## Добавление раздела

1. Создайте файл с латинским именем в `docs/`, например `accessibility.md`.
2. Добавьте один H1, назначение раздела, проверяемые правила и примеры.
3. Добавьте файл в `nav` файла `mkdocs.yml`.
4. При необходимости добавьте относительные ссылки с других страниц.
5. Выполните локальные проверки и просмотрите сайт.
6. Зафиксируйте изменения и отправьте ветку в GitHub.
7. Создайте PR в main и укажите изменение и результаты проверок.

## Ревью

Другой студент проверяет ясность, примеры, терминологию, ограничения и доступность текста. Замечание должно содержать место, проблему и объяснение или предложение. Для учебного обмена оставьте минимум три содержательных комментария к PR партнёра. Комментарии отправляются автором аккаунта или по его явному поручению.

Исправьте замечания отдельным коммитом в той же ветке. В обсуждении объясните правку или обоснованное отклонение. Не выдавайте самостоятельную проверку за независимое ревью. После одобрения другого студента и успешных проверок объедините PR в main с сохранением истории коммитов. Проверьте успешную публикацию и наличие нового раздела на сайте.
