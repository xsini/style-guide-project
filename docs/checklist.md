# Проверка перед публикацией

## Редакторская проверка

- [ ] Названы читатель и задача документа.
- [ ] Есть один H1, уровни заголовков не пропущены.
- [ ] «Заявка на поездку» и «отклик» не смешаны.
- [ ] Кодовые статусы записаны без изменения регистра.
- [ ] Указано, какие факты взяты из отчёта, а какие проверены по коду.
- [ ] Планы отделены от функций описанной версии.
- [ ] Ограничения localStorage указаны там, где влияют на сценарий.
- [ ] Нет обещаний сетевого чата, push-уведомлений и модерации без подтверждения.
- [ ] Шаги имеют предусловия и ожидаемый результат.
- [ ] Ссылки понятны без окружающей фразы.
- [ ] Нет реальных персональных данных и секретов.
- [ ] Изображения и таблицы понятны вместе с текстом.

## Автоматическая проверка

Перед PR выполните `npm run lint:md`, `python scripts/check_docs.py` и `python -m mkdocs build --strict` в настроенной среде. Все три команды должны завершиться с кодом 0. Линтер проверяет разметку; предметную точность, понятность и полноту проверяет человек.

## Ревью и публикация

Проверьте изменение с другим студентом или участником команды. Исправления оформите отдельным коммитом. После одобрения и успешных проверок объедините PR. Успешный деплой подтверждается рабочим процессом GitHub Actions и открывающейся обновлённой страницей.
