# Проверка применения стайлгайда

Дата: 20.11.2026. Метод: редакторская проверка двух фрагментов документации по исходному отчёту ПР 10. Объект проверки — тексты документации, а не работоспособность приложения.

## Пример 1 Описание продукта

Исходный фрагмент: «Демонстрационная версия реализуется как одностраничное веб-приложение на React и TypeScript. Данные пользователей, заявок, откликов, чатов и уведомлений сохраняются в localStorage браузера».

В [новом описании](readme-fragment.md) сохранены стек и способ хранения. Сведения разделены на назначение, возможности, технологии и ограничения. Добавлено пояснение про один браузер. Отсутствующие функции перечислены отдельно на основании раздела 8.2 исходного отчёта.

## Пример 2 Сценарий отклика

Исходный фрагмент: «После принятия отклика создаётся локальный чат; до принятия доступ к нему закрыт».

В [инструкции](response-instruction.md) добавлены предусловия, участники, восемь последовательных шагов, ожидаемый результат и негативные случаи. Сведения о запрете самоотклика, дубля и отклика на закрытую заявку взяты из разделов 4.4 и 5 исходного отчёта.

## Результаты редакторской проверки

| Критерий | Описание продукта | Инструкция |
| --- | --- | --- |
| Единые термины | Соответствует | Соответствует |
| Задача читателя | Указана | Указана |
| Структура по шаблону | Соответствует фрагменту README | Есть условия, шаги, результат и ошибки |
| Границы прототипа | localStorage и отсутствующие функции | Один браузер и локальный чат |
| Подтверждение поведения | Указан исходный отчёт | Ожидаемое поведение отделено от запуска |
| Планы отделены от реализации | Да | Да |

Оба фрагмента прошли шесть редакторских критериев. Это результат проверки документов одним автором; он не заменяет независимое ревью и тестирование приложения.

## Уточнения правил по результатам

После применения шаблонов уточнены правила: не выдавать участников сценария за роли доступа; не называть локальный чат сетевым; не придумывать подписи кнопок; различать ожидаемый и фактический результат. Эти требования включены в разделы о читателях, ограничениях, Markdown и структуре.

## Дальнейшая проверка

Перед выпуском пользовательской инструкции нужно сверить её с фактической версией приложения, названиями элементов интерфейса и результатами выполнения сценария. Для независимой оценки нужен отзыв другого студента.
