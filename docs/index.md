# Руководство по стилю документации Travel Buddy Finder

Версия руководства: 1.0. Дата: 20.11.2026. Владелец: Яковенко Ксения Александровна.

Это руководство помогает авторам согласованно описывать Travel Buddy Finder: веб-прототип поиска попутчиков. Оно распространяется на README, пользовательские инструкции, описание архитектуры, сценарии проверки и сообщения об ошибках.

## Границы продукта

Исходное описание версии взято из отчёта «ПР 10 Реализация проекта». В нём описан клиентский прототип на React и TypeScript с хранением данных в localStorage. Серверная часть, PostgreSQL, JWT, внешние уведомления и модерация в эту версию не входят. Перед изменением документации автор сверяет описание с кодом и результатами проверки соответствующей версии.

## Как пользоваться руководством

1. Определите читателя и задачу документа.
2. Проверьте названия сущностей по [словарю терминов](terminology.md).
3. Выберите [шаблон документа](templates.md).
4. Уточните [границы прототипа](product-scope.md).
5. Пройдите [контрольный список](checklist.md) и автоматические проверки.

## Обязательность правил

Слово «обязательно» обозначает требование. «Рекомендуется» допускает обоснованное отступление. В PR с отступлением укажите причину, читателя и способ сохранения понятности. Решение фиксируется в обсуждении PR.

## Порядок приоритетов

Факты о конкретной версии продукта и согласованные требования имеют приоритет над примерами. Далее применяются правила этого руководства. Если вопрос не описан, автор обращается к источникам из [списка литературы](sources.md) и предлагает уточнение через PR.
