# Оформление Markdown

## Заголовки и абзацы

Используйте ATX-заголовки с пробелом после `#`. Между абзацами и вокруг заголовков, списков и блоков кода оставляйте пустую строку. Не выравнивайте текст пробелами и табуляцией.

Список действий нумеруйте, перечень свойств оформляйте маркером `-`. Вложенность нужна только для зависимости элементов. Одно действие может включать короткое пояснение результата.

## Выделение и код

Названия видимых элементов интерфейса выделяйте полужирным и сверяйте с актуальным интерфейсом. Идентификаторы, пути, команды и статусы оформляйте обратными кавычками. У блока кода обязательно указывайте язык: `powershell`, `bash`, `json` или `text`.

## Таблицы

Используйте таблицы для сопоставимых записей. У каждого столбца должен быть заголовок. Во всех строках нужны начальная и конечная вертикальные черты. Разделитель состоит из обычных дефисов. Длинную последовательность действий оформляйте списком вне таблицы.

## Ссылки

Внутренние ссылки задавайте относительным путём к Markdown-файлу, например `[словарь](terminology.md)`. Используйте понятную подпись. Не используйте Obsidian-ссылки вида двойных квадратных скобок: в проекте настроены обычные Markdown-ссылки.

Для внешнего источника укажите название и URL. Утверждение должно соответствовать содержимому источника. Ссылки и якоря проверяются при строгой сборке MkDocs.

## Изображения

Снимок экрана должен относиться к описываемой версии. Дайте подпись, альтернативное описание и текстовое объяснение нужного действия. Не включайте в изображение реальные пароли, переписку и персональные данные. Демоаккаунт явно называйте демонстрационным.
