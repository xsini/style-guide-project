# Источники и область их применения

## Материалы работы

- «Лабораторная работа 3 (1).docx»: состав задания и требования к Docs as Code.
- «Стайл-гайд1 (1).pptx»: назначение, этапы разработки и примерная структура стайлгайда.
- «Практическая_работа_5_Travel_Buddy_Finder.docx»: бизнес-процессы и модели.
- «ПР_6 Бусова, Кисель, Марков, Яковенко.pdf»: роли, пользовательские истории и релизы.
- «ПР_7 Бусова, Кисель, Марков, Яковенко.pdf»: техническое задание и критерии приёмки.
- «ПР_9 Бусова, Кисель, Марков, Яковенко.pdf»: UML-модели целевой системы.
- «ПР_10_Яковенко_Travel_Buddy_Finder.docx»: сведения о реализованном объёме и ограничениях клиентского прототипа.

Образец «Кисель_Персук_лр3.docx» использован для понимания полноты отчёта. Сведения о SONDER, чужие ссылки, комментарии и результаты деплоя к Travel Buddy Finder не относятся.

## Основной источник теоретических ответов

[Ира Саникович. Тернистый путь к созданию и внедрению Content Style Guide. Хабр, 26.11.2021](https://habr.com/ru/articles/591761/). Статья используется для обоснования необходимости общего справочника и практического внедрения. Применение её подхода к Travel Buddy Finder и предложения по ИИ являются самостоятельными решениями для учебного проекта.

## Внешние руководства

- [Google Developer Documentation Style Guide](https://developers.google.com/style): ясность, единообразие и приоритет правил проекта.
- [Стайлгайд Ozon](https://docs.ozon.ru/styleguide/): разделение правил написания и оформления документации.
- [Документация MkDocs](https://www.mkdocs.org/): конфигурация, строгая сборка и структура сайта.
- [GitHub Pages с GitHub Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages): сборка артефакта и отдельный этап публикации.
- [markdownlint-cli2](https://github.com/DavidAnson/markdownlint-cli2): запуск проверки Markdown.
- [Conventional Commits 1.0.0](https://www.conventionalcommits.org/ru/v1.0.0/): структура сообщения коммита.
