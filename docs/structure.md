# Структура документа

## Общие требования

У страницы обязательно один заголовок первого уровня. Следующие уровни идут без пропусков: H1, H2, H3. Заголовок называет предмет: «Отправка отклика», «Ограничения прототипа». Не используйте «Разное» для набора несвязанных тем.

В начале укажите задачу документа и область применения. Для меняющегося поведения укажите версию или источник описания. Объединяйте связанные сведения в разделы, а не в длинную вводную часть.

## Пользовательская инструкция

1. Название действия.
2. Назначение и ограничения версии.
3. Условия перед началом.
4. Нумерованные шаги.
5. Ожидаемый результат.
6. Ошибки и способ продолжить работу.

## Техническое описание

Укажите назначение, используемые технологии, модель данных, порядок запуска, проверки и ограничения. Не добавляйте фиктивный REST API в описание клиентского прототипа.

## Отчёт о проверке

Укажите объект, среду, дату, предусловия, шаги, ожидаемый результат, фактический результат и свидетельство. «Не проверено» является допустимым статусом. «Пройдено» требует фактического выполнения.

## Требования и модели

У требования сохраняйте идентификатор, источник, условие, ожидаемое поведение и критерий проверки. Если идентификатор в источнике отсутствует, не выдавайте новый локальный номер за исходный.

У модели укажите тип диаграммы, сценарий, рассматриваемую версию и назначение. Подпись к диаграмме должна объяснять смысл без просмотра рисунка. Кодовые имена классов и статусов согласуйте со словарём. Изменение модели должно сопровождаться проверкой связанных требований и инструкций.
