# Термины и названия

## Словарь продукта

| Термин | Значение | Правило употребления |
| --- | --- | --- |
| Travel Buddy Finder | Название проекта | Сохраняйте регистр и пробелы |
| Заявка на поездку | Описание поездки и поиска попутчика, TripRequest | После определения можно писать «заявка» |
| Отклик | Ответ путешественника на чужую заявку, Response | Не заменяйте словом «заявка» |
| Автор заявки | Пользователь, создавший заявку | Не называйте администратором |
| Профиль путешественника | Сведения о пользователе, Profile | Не обещайте проверку личности |
| Локальный чат | Сообщения участников принятого отклика | Не называйте сетевым чатом в реальном времени |
| Уведомление в интерфейсе | Запись Notification внутри прототипа | Не заменяйте термином push-уведомление |
| localStorage | Хранилище данных в браузере | Сохраняйте регистр идентификатора |
| MVP | Минимально жизнеспособная версия | В этом проекте уточняйте: клиентский MVP-прототип |

## Статусы

Кодовые значения записывайте моноширинным шрифтом: `active`, `accepted`, `rejected`. Пользователю объясняйте смысл: «отклик принят (`accepted`)». Не придумывайте кодовые значения других статусов: сверьте их с реализацией.

## Иноязычные слова

В тексте предпочитайте «серверная часть» вместо backend и «репозиторий» вместо repo. Названия React, TypeScript, Vite, GitHub и MkDocs сохраняйте. При первом употреблении расшифруйте непривычную аббревиатуру. Идентификаторы кода не переводите.

## Словарь между этапами

В материалах встречаются «заявка на путешествие» и «заявка на поездку». Для нового повествовательного текста принято «заявка на поездку». В точных цитатах, названиях исходных требований и обозначениях диаграмм сохраняйте исходный вариант и при необходимости поясняйте соответствие.

В ПР 9 модель использует `ACTIVE`, `CLOSED`, `CANCELLED`, `SENT`, `ACCEPTED`, `REJECTED`. В ПР 10 встречаются `active`, `accepted`, `rejected`. Не меняйте регистр при цитировании идентификаторов. При сопоставлении укажите источник: «принят: `ACCEPTED` в UML-модели; `accepted` в описании прототипа». Равенство кодовых значений между версиями нельзя считать проверенным без кода.

Автор заявки и откликающийся — сценарные роли путешественника, что явно отмечено в ПР 6 и ПР 9. Администратор/модератор входит в целевые модели, но не реализован в прототипе по ПР 10. Не удаляйте его из описания целевой системы и не добавляйте в описание возможностей текущего прототипа.
